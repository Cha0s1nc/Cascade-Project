# Cascade code map

This map covers the desktop app, which lives in `desktop/`: every path below is relative to `desktop/` unless it starts with another top-level folder. The iOS and tvOS app lives in `apple/` and has its own map, `apple/CODEMAP.md`. The Cascade Server Jellyfin plugin lives in `server/` (C#, Jellyfin 12 only; built, tested and released by `.github/workflows/server.yml` to the catalog at `plugins.chaosinc.xyz`); see `server/README.md`. `shared/` holds what more than one app reads: `shared/assets/` (the artwork and icons, copied into `desktop/assets` by `build:shared` for packaging), `shared/tuning-defaults.json`, `shared/fixtures/` (the offline fixtures the TypeScript and Swift tests both check), and `shared/scripts/` (release planning, the changelog, tuning, and the root `npm test` runner). The release and repo plan is in `docs/release-pipeline-plan.md`.

**Describes `dev` at `edd2fad`. Every line number below was re-derived at that state, not carried over. Line numbers rot fast: if a landmark is not where this says, re-grep and fix the line here rather than trusting it.**

Last re-derivation found the drift from `a3f5f52` was NOT a constant offset - `connect()` had moved +137 lines while `_detachDeck()` had moved -111. A stale map cannot be corrected by arithmetic; it has to be re-grepped.

Written so an agent can start work without re-reading the whole tree. It is a map, not documentation: it says where things are, how they are wired, and **which shapes exist because a specific bug forced them**. That last part is the point. Most of what follows is a scar.

## Shape of the project

| File | Lines | What it is |
|---|---|---|
| `renderer.js` | ~9809 | The whole UI. Plain global scope, **no semicolons**, no modules. |
| `index.html` | ~1479 | All markup. No CSS: it links `styles/*.css`. |

Verify with `npm run build:ts && npm run typecheck && npm test` in `desktop/`. From the repo root, `npm test` runs every app's tests (`npm test desktop`, `npm test apple` for one).

**Run `npx tsc --noEmit` directly, never piped to `tail`.** Errors print above the last line, so `| tail -1` hides them. A broken assertion shipped that way.

**The coupling no AST can see:** `index.html` defines ids and classes, `renderer.js` reaches them by `getElementById` / `querySelector` string literals. Renaming an id is a silent break that typecheck will not catch.

## Edition labels

The server's Devices and Activity screens tell Cascade's editions apart by the auth header's `Client`: `Cascade Electron` (this app, every OS), `Cascade iOS`, `Cascade tvOS`, and `Cascade Mac` for the native port on `mac-swift-port`. `Device` is the machine (`Windows`, `Mac`, `Linux`, `iPhone`, `iPad`, `Apple TV`). Desktop sets it once in `init()` through `CascadeCore.setClientIdentity()`, before anything authenticates; `authHeader()` reads it, and the lyrics and metadata editor windows get it in the `jf` they are opened with. Apple's is `cascadeEdition` in `JellyfinClient.swift`. The server keys a device on `DeviceId`, so the Mac port keeping Electron's id renames the device rather than adding one. Nothing matches on the old plain `Cascade`.

## Rules this codebase learned the hard way

1. **Read the response of anything that writes.** Five separate write paths were found reporting success on an HTTP 403 because nothing checked `res.ok`, and one removed a track from the queue regardless of what the server said, so a refused delete looked exactly like a successful one.
2. **Never trust an endpoint's shape from memory.** "Mark as played" was written against `/Users/{id}/PlayedItems/{id}`, which does not exist on Jellyfin 10.11. The server's own OpenAPI spec is the source of truth.
3. **A layout class must be set or cleared BEFORE a skeleton is drawn**, not after the fetch resolves, or the placeholder is laid out by whatever the previous screen left behind.
4. **`ready-to-show` can never fire on Windows.** See `showWhenReady()`.
5. **Windows and Linux draw OS caption buttons OVER the page, top right.** Use `--caption-reserve`. This has bitten three separate controls.
6. **A `-webkit-app-region: drag` surface hands its mouse events to the OS.** Nothing under it receives hover, click or mousemove.
7. **A pseudo-element cannot escape its host** - not its clipping, not its stacking context. No z-index fixes it from the inside.
8. **A canvas painted from a DOM `<img>` is tainted.** Art elements are written by `innerHTML` with no `crossorigin`, so `getImageData` throws and colour extraction silently returns nothing - a theme toggle that looks simply dead. Always go `fetch -> blob -> objectURL -> Image`; see `themeFromArtUrl()`. Do NOT "fix" it with `crossorigin="anonymous"` on the tags: that sends an Origin header the server may not answer, breaking the image itself.
9. **A guard that names an element id is only as good as the id.** The side panel's karaoke fill was gated on `getElementById('view-lyrics')`, which has never existed - the optional chain yielded `undefined` and the feature never ran once, for as long as it shipped. `?.` on a lookup turns a typo into permanent silence. Grep the id before trusting a guard that uses one.

## renderer.js landmarks

### Session, permissions, setup
- `connect(serverUrl, token, userId)` - **641**. Sets the global `jf`. Fires `/Users/{id}/Views` in PARALLEL with the token ping rather than after it. The ping's response carries `Policy`, which is where `isAdmin` and `canDelete` come from, so both are free - do not add a request for them.
- `_applyAdminGating()` - **828**. Gates the library scan, both Refresh metadata entries, Edit metadata/images, and playlist delete. **A new admin-only control must be added to this function's id list or it is not gated at all.** Uses the `.needs-admin` class plus an inline note.
- `maybeShowSetupWizard()` - **1309**, `WIZARD_REVISION` - **1273**, and `FIRSTRUN_STEP_REVISION` - **1280**, the revision each step arrived in. An update shows only steps newer than the revision last finished. Runs from `connect()` off a stored revision, NOT the app version and NOT a boolean. Safe to re-show on update only because every step seeds from the current live value. **Never add a step that writes a default on entry.**
- **Telemetry is built but dormant.** `CascadeCore.TELEMETRY_URL` (`src/core/telemetry.ts`) is empty, so `telemetryAvailable()` is false: the wizard's `telemetry` step is filtered out, `#s-telemetry-row` stays hidden, and `loadTelemetry()` / `countTelemetrySong()` / `maybeSendTelemetry()` do nothing. The switch-on checklist is in that file and `telemetry/NOTES.md` (the Worker, not deployed). Switching it on also needs `WIZARD_REVISION` bumped, or existing installs are never asked.
- **Announcements** (the title bar bell): `shared/announcements.json`, uploaded to R2 by `.github/workflows/announcements.yml` on a push to dev, fetched by main's `announcements-fetch` (R2 sends no CORS headers; gated on Offline Mode like update checks), parsed by `src/core/announcements.ts`, drawn by `loadAnnouncements()` / `renderAnnouncements()`. Dismissed and seen ids live in the store. Committing an entry to that file posts it to everyone.
- `setBrowseMode()` - **1106**. The Music/Video toggle. A browsing filter only: it never touches playback or the queue.

- `currentDeviceProfile()` - **464**. The profile minus any codec proven undecodable at runtime.
- `_armAudioDecodeCheck()` - **9494**. Detects "video plays, no sound" using `webkitAudioDecodedByteCount`, NOT the analyser level: a quiet scene and a broken decoder both read as zero level, but only a broken decoder has decoded zero BYTES while the clock ran. On failure it withdraws the codec claim, persists it, and re-negotiates.
- **Crossfade stutter is still open**, and six candidates are already ruled out by reading: ramp resolution, the readiness bar, colour extraction at handoff, list virtualisation, EQ parameter ramping, and graph rewiring. It needs a `readyState` reading off the debug panel, not another guess.

### Web Audio / EQ
- `_ensureEqGraph()` - **5560**. AudioContext -> per-deck source -> per-deck gain (the crossfade envelope) -> preamp -> 5 biquads -> analyser -> out. Built once, never rewired.
- Three failure flags at **5523**, and the distinction is load-bearing: `_eqGraphFailed` (no graph at all, blocks bars AND crossfade), `_eqNoSignal` (cosmetic, bars only), `_eqEverHadSignal`. Conflating the first two silently killed crossfade for a whole session once.
- `stopEqLoop()` resets `_eqSilentSinceTs`. Without it, a pause during a silent intro left the silence timer counting, and resuming more than `EQ_SILENCE_MS` later latched `_eqNoSignal` on the first frame and froze the bars for the session. Reproduced before fixing.

### Lyrics
- `lyricsPanelOpen()` - **7889**. The single visibility test both lyrics loops use: `_paintWordSpans`/`_wordHighlightFrame` (**7828**/**7838**) and the `timeupdate` line-promotion handler. `.lyrics-panel` is `position: fixed` ABOVE every view (`styles/lyrics.css` **2**), so it is NOT hidden by navigating elsewhere and `.open` is the entire condition. The guard matters for correctness (the karaoke fill never ran before it); as a CPU saving it measured below noise, see "Measured, not worth building" below.
- **Translation** is Mozilla's Firefox Translations models on the bergamot WASM runtime, into English only, for `ja`, `ko`, `zh-Hans`, `zh-Hant`, `es`. Adding a language: its files in `translation-models.json` (copied from Remote Settings with hashes), uploaded to the models release as `<key>-en.<file>`, and the key in `src/core/translation-models.ts`.
  - What each line sends is `planSheet` (`src/core/lyric-translation.ts`): for a non-Latin-script sheet, a line with no foreign-script letters is skipped, a mostly-English line with one foreign phrase sends only the phrase, anything else the whole line. Latin-script sheets send every line. Latin-script lines are compared with their English afterwards (`latinView`): passed through shows nothing, a changed phrase in an English line gets its English under it, a changed line gets its English cut across its rows (`splitForRows`, by share of characters, not word alignment). `_lineGlossFor` decides, `_layoutGlosses` draws: absolutely placed `.lyric-gloss` elements measured off Ranges (the karaoke spans are never touched), with `.glossed` opening a gap under every row, laid out again by a ResizeObserver on both lyric bodies. Non-Latin whole lines keep the plain row (`lyricTranslationFor`).
  - `translation-models.json` pins every model file by size and sha256. Updating a model is a manifest edit plus a new GitHub release, never a runtime lookup of Mozilla's Remote Settings (Firefox internals).
  - main.js `downloadTranslationModel()` - **1041**. Tries Cascade's GitHub release, then Mozilla's CDN, per file. **The hash check is not optional:** `downloadFile()` resolves on a truncated stream. Files land in `<key>.partial/` and the directory is renamed only once all verify, so an installed model is exactly a directory that exists. Keys from IPC are checked against the manifest before touching a path.
  - The models' GitHub release must live in a **separate repo**, never `Cascade-Project`: the updater reads that repo's latest (or first non-draft) release as an app update.
  - `cascade-model://` (`registerModelProtocol`, main.js **60**) serves `/runtime/` (the wasm) and `/models/` (installed models) behind `serveWithin()`'s escape guard, plus a registry per model (`translationRegistryResponse`, **1110**): translator.js keys registries by from+to, so the two Chinese models can never share one.
  - `scripts/build-bergamot.js` vendors the runtime. It bundles translator.js to the `Bergamot` global with `import.meta.url` defined as `self.__bergamotBase` (set in index.html), and points the worker's wasm fetch at `cascade-model://`, since fetch from file:// is blocked. Each patch asserts it matched, so a runtime upgrade that moves the code fails the build.
  - Renderer: `translateLines()` - **6644**, one `BatchTranslator` per model, retired after `TRANSLATE_IDLE_MS` (**6586**); one line per call; an in-memory LRU of translated lines for the session. `ensureLyricsTranslation()` - **8564** downloads a missing model before translating. `CascadeCore.translationLanguageFor()` names a sheet's language (Chinese scripts told apart by characters written differently in each, Russian and Ukrainian by their own letters), and `pickTranslationEngine()` picks Apple, Mozilla, an install prompt, or none (no Translate button). Mozilla covers `TRANSLATION_MODEL_KEYS`; Apple is asked about `APPLE_TRANSLATION_KEYS`, and the renderer caches its answer in `_appleLanguageStatus` so the button needs no round trip.
  - Two switches, on purpose: `lyricsTranslationEnabled` (Settings/wizard, default on) is whether the feature exists; `lyricsTranslateOn` (the Translate button, default off) is whether translations are showing. `setLyricsTranslationEnabled()` - **8399** is the one path for both Settings and the wizard.
  - **Apple Translation (macOS 26+, default on there).** `native/apple-translate` is a Swift helper (`TranslationSession(installedSource:target:)`, the windowless macOS 26 API) built by `scripts/build-apple-translate.js`: a no-op off macOS, fails in CI without the 26 SDK, warns and skips locally. It is `asarUnpack`ed, since nothing inside app.asar can be executed. main.js keeps one long-lived helper, spoken to with one JSON line each way over stdin, and ends it after five idle minutes and on quit.
    - `CascadeCore.pickTranslationEngine()` decides per sheet: Apple if the language is installed in macOS; Mozilla if Apple is off, has no model for it ("unsupported"), or the user chose Cascade's model for that language; otherwise `needs-install`. The chosen-Mozilla list only applies while a language is missing from macOS.

- A lyrics MISS is cached, not just a hit (`_cachePut(item.Id, null)` at the tail of `fetchLyricsWaterfall`). ## Added on overnight-2026-09-27 (line numbers at 8b57f2c)

Everything above still describes edd2fad. This section covers what the overnight batch added, with line numbers re-derived at 8b57f2c. Every item was checked against a throwaway Jellyfin 10.11.11, not only by tests.

### Crossfade: the two bugs behind "restarts when the crossfade ends"
- `onDeck('pause', ...)` - **5468**. Skips `cancelCrossfade()` when `audio.ended` is true. The spec fires `pause` just before `ended` when a track runs out, and treating that as a manual pause tore down fades that were finishing normally, so `ended` cold-started the next track at 0:00. Intermittent because the fade's own handoff timer often lands within milliseconds of the natural end. **This was the longstanding bug.**
- `_prefetchNext()` - **5886**. Bails while `_cfOtherDeck` is set, and rechecks the target deck after its await. Mid-fade, "the deck that is not `audio`" is the INCOMING deck, so any queue mutation (`_reprefetch()`) reloaded the fading-in track onto itself.
- Gapless was measured, not rebuilt: on a prefetch hit the `ended` handoff takes under 1 ms and flac is seamless; mp3 carries ~16 ms of LAME priming. Do not build an MSE/early-start pipeline without new evidence.

### Playback additions
- Normalization: `src/core/normalization.ts` (clamped +12/-24 dB, unity for anything non-finite). A per-deck `GainNode` sits `source -> norm -> fade gain` inside `_ensureEqGraph()` **7140**, which re-applies it because the graph is built on the first `play`, AFTER the first track asked for it. `_applyNormalizationToDeck()` **7267**. Default off.
- Output device: `AudioContext.setSinkId` (not the elements, everything routes through the context). `_outputDeviceSupported()` **7304**. A vanished device falls back to the system default and says so.
- m4a: `src/core/profiles/electron.ts` claims `m4a,mp4` only for aac/mp3/flac/opus. ALAC shares the container and Chromium has no decoder for it (`canPlayType` answers ""), so it must keep transcoding.

## Added for reverse proxies (headers and client certificates)

- `src/core/custom-headers.ts` is the pure part: name and value validation, `parseHeaderLines` (one `Name: Value` per line), `headersForRequest` (same origin as the Jellyfin server only, `ws`/`wss` counted as `http`/`https`), `withCustomHeaders`, `chooseClientCertificate`. main.js requires it as `build/custom-headers.js`.
- main.js `installConnectionHeaders()` adds them in `session.defaultSession.webRequest.onBeforeSendHeaders`, the only place that also reaches `<img>`, `<audio>` and `<video>`. `Authorization`, `X-Emby-Authorization`, `Host`, `Content-Length` and `Transfer-Encoding` are refused. The origin comes from `connectionServerUrl`, kept in step by the `serverUrl` store key and by `connection-set`, which the setup form and Settings call BEFORE the first request: a proxy that wants the header refuses the sign-in itself.
- The sign-in screen's Quick Connect check runs as the address is typed, so it sends the headers only to the server they were saved for (`probeHeaders`) and saves nothing (`connection.set(url, headers, false)`). For a new server it offers the button anyway; pressing it applies the headers for real.
- Headers live in the store key `customHeaders`, in plain text like the token. Never sent to lyrics providers, GitHub, Mozilla or the Waterfall relay (tested in `test/custom-headers.test.ts`, and against the real app: fetch, img and audio all carry them).
- Client certificates: `select-client-certificate` answers only for the server's origin. Electron cannot be handed a `.p12` file, only a certificate already in the operating system's store, so the person imports theirs there; Cascade picks (asking when several, remembering the fingerprint in `clientCertFingerprint`). Chromium does not call the handler when the store holds nothing. The pick and the dialog are NOT verified: no certificate could be installed in the test environment.

## Offline downloads (desktop)

Mirrors the Apple app's design (`apple/CODEMAP.md`, "Offline downloads").
- `src/core/offline-index.ts` is the pure part, tested like Apple's `OfflineIndex`: one index of relative paths, a shared track stored once, a removal deleting only files nobody else holds, `reconcile` against the disk, `parseIndex` validating what was read, `judgeDownload` (2xx, the full announced length, something that says audio), `parseByteRange`. main.js requires it as `build/offline-index.js`.
- `offline.js` (main process, no semicolons, in `build.files`) owns `userData/offline/<userId>/{index.json,media,art}`: one folder per account. The renderer names the owner with `offline.setOwner()` at launch (from the store, so offline mode finds that account's music), on every `connect()`, and `null` on sign-out. Switching writes the outgoing index, aborts its downloads and drops the token; with no owner every call answers empty and the protocol serves nothing. Work that awaited across a switch checks it still holds the same `index` object before touching disk or state. Downloads use `/Items/{id}/Download` (the only route that honors the admin's download switch), two at a time, to `media/<id>.partial`, renamed only after `judgeDownload` passes. Reverse-proxy headers and the client certificate apply (it uses `net.fetch`). Launch deletes `.partial` files and strays and sends a missing file's track back to pending. The renderer's token is passed per call and kept in memory only.
- Playback: `resolveTrackStream()` returns a `cascade-offline://local/media/<file>` URL for a downloaded track before the server is asked anything. The scheme is registered with `stream` (a media element cannot read it otherwise) and its handler serves only files the index lists, checks the path by shape and by escape guard, and answers `Range` itself with a real 206: leaving that to `net.fetch` made seeking silently fail (found by running it). It sets `Access-Control-Allow-Origin` so the Web Audio graph can read the element. Covers are `cascade-offline://local/art/<id>.jpg`, and `artUrl()` prefers them.
- Renderer: the section "Offline downloads" in renderer.js, the Downloads view (`#view-downloads`), the buttons on the album and playlist pages, and `ictx-offline` in the item menu. `_offline` is the summary and is declared at the top of the file because `artUrl()` and `resolveTrackStream()` read it from the first render.
- Offline mode: `connect()` now throws with the HTTP `status` when the server answered, none when it never did. Launch shows the sign-in prompt only for 401/403; with no network and downloads on disk it opens the Downloads (`body.offline-mode` dims the rest), and `online` or "Try again" reconnects.
- Offline plays: a failed start report (`reportStart` now resolves true or false) queues the play in the main process, and it is replayed as `POST /UserPlayedItems/{id}?userId&datePlayed` on reconnect and after a later report succeeds. 400 and 404 drop a play, anything else keeps it.
- Not built: transcoded downloads, offline lyrics, an offline mode for the library tabs. Volume normalization offline falls back to unity unless the gain was in the downloaded item.

## Offline Mode, phase 1 (catalog version 2 and the query engine)

The plan is `docs/offline-mode-plan.md`; the requests the engine answers are listed in `docs/offline-request-map.md`. Nothing in the app calls either piece yet (phase 2 wires them).
- `src/core/offline-index.ts` is now catalog version 2. It keeps version 1's `tracks` / `collections` / `plays` shape, so `offline.js` and the renderer read it unchanged, and a version 1 `index.json` (no `version`) reads as is (`test/fixtures/offline-index-v1.json`). `tracks` holds every file-backed item, movies and episodes included, despite the name. `slimItem` keeps every field a screen reads, type-checked, because it also reads what came off the disk. Video keeps its streams and chapters; audio does not need them.
- Libraries: each track may carry `library`. `libraryOf()` answers that, or the placeholder for its kind (`PLACEHOLDER_LIBRARIES`, ids `cascade-offline-music` / `-movies` / `-shows`) when it is missing or no longer listed. Everything from version 1 starts in the placeholder.

- `src/core/offline-query.ts`: `offlineQuery(index).answer(path, params)` answers a GET in Jellyfin's shape. It answers only ready items. Unknown routes come back as an empty list marked `unknownRoute`, never a network call. Keep one engine per catalog state: parts are built lazily and kept (about 50 ms to build for 20,000 songs, then about 10 ms a request). Sorting compares lowercased text by code point, never `localeCompare`, so the Apple engine orders identically.
- `test/fixtures/offline-query.json` is shared with CascadeKit's `OfflineQueryTests`. **A change to either engine's behavior needs a case there, and both engines passing it.**

## Offline Mode, phase 2 (the switch, the swap, the guard)

- `src/core/offline-mode.ts` (pure, tested): the three states (`online`, `manual`, `unreachable`), `nextOfflineState`, the probe backoff (30 s doubling to 5 minutes), `failureKind` (no answer, 502, 503 and 504 are unreachable; 401 and 403 are the session, never Offline Mode), `blocksServer` (manual only) and the update-check rules. - The guard: everything else the renderer sends to the server goes through `jfFetch` (`renderer.js`, near `const jfFetch`), anything else on the web through `webFetch`; both refuse while offline. `test/offline-guard.test.ts` fails on a raw `fetch(` in `renderer.js`, `waterfall.js` or `lyric-karaoke.js` unless a comment right above it says `offline-ok:` and why.
- Main's backstop: while manual, `onBeforeRequest` in `main.js` cancels every request to the server's origin (images and media elements included). Off while unreachable, so the probe gets through. Update checks wait while offline and run once on the way back online.

## Offline Mode, phase 4 (sending what happened offline)

- `src/core/offline-sync.ts` (pure, tested in `test/offline-sync.test.ts` against `test/fixtures/offline-sync.json`, shared with CascadeKit's `OfflineSyncTests`): `coalesceChanges` (per item, later wins, a favorite back where it started is no change), `updateToSend` (the conflict rule: a change wins only over an older server LastPlayedDate; fields the server already holds are left out), `snapshotMatches` and `playsCatchUp` (`none`, `replay`, `hold`; no snapshot never matches; rows are put in one fixed order first, since the server orders equal dates either way), `playsOldestFirst`, `HISTORY_QUERY` (the top 200 of Audio, Movie and Episode by DatePlayed, across every library, one request).
- Catalog (`offline-index.ts`): `changes` (`UserDataChange`: position, played, favorite with `was`) and `playsHeld`, both validated by `parseIndex` (`parseChange`). `addPlay`, `addChange` and `setHistory` write into the stored items' UserData (tracks, collections, containers), and `refreshUserData` replaces it with the server's, then lays the queue back on top, so offline History, Continue Watching and the hearts show what was done offline. `overStorageLimit`, `userDataIds`.
- `offline.js`: IPC `offline-change-add`/`-changes-take`, `offline-set-history`, `offline-set-user-data`, `offline-plays-hold`/`-discard`, `offline-limit`. The storage limit is checked before a download starts (a song's size, a video's estimate) and as bytes arrive (a transcode announces nothing); raising it retries what it stopped.
- Renderer, section "What happened while the server was out of reach": `syncOffline()` is awaited in `connect()` before Home loads. It compares the server's history with the snapshot (only when plays wait), holds or replays, then in the background sends changes (`POST /UserItems/{id}/UserData`, `/UserFavoriteItems/{id}`), replays plays oldest first, refreshes every download's UserData (`jfItemsByIds`) and takes a new snapshot. **The snapshot is never retaken while plays wait for that compare** (`takeHistorySnapshot` checks the summary), or the compare would match whatever happened elsewhere. It is retaken 5 s after a start or stop report lands, on Home and History, and right before the Settings switch turns Offline Mode on. A successful start report no longer replays plays: a play queued during a short blip waits for the next connect. `toggleLike` and `setItemPlayed` queue offline; `reportPlaybackStopped` queues a video's position (or played at 90 percent) when the stop report fails. Favorite and mark played are no longer hidden offline (`context-menu.ts`). Downloads shows held plays with Add and Discard, and the storage limit (store key `downloadLimitGB`, none by default).

## Measured, not worth building

Taken with the debug panel's resources section on Apple Silicon, playing real audio on the live deck. Recorded so these are not rebuilt on a hunch.

- **Parking animation loops while minimized.** rAF does keep running at 61fps behind a minimized window (`backgroundThrottling: false`), but with the EQ bars, overlay blob drift and karaoke loop all live, renderer CPU was 3.4% whether the loops ran or not. Chromium already skips raster for an unseen window, and the loops' own JS is below noise. Built, measured, reverted.
- **Detecting minimize from the page.** `visibilitychange` never fires and `document.visibilityState` stays `visible` while minimized, because Electron ties the Page Visibility API to `backgroundThrottling`. Anything that needs it must come from main's window events.
- **Overlay blob background.** Animating versus holding one frame, window maximized at 1920x1169: GPU 5.0% versus 4.6%. Noise.
- Where the cost actually is: audio playback itself (~1% renderer CPU over paused), a constant ~4-5% GPU process baseline that does not move with any of the above, and translation memory while a model is loaded (translators are retired when idle). Low-end hardware was not measured and could differ.

## main.js landmarks

- `showWhenReady(w, after)` - **361**. **The only correct way to show a window created with `show: false`.** `ready-to-show` fires on first paint, and a hidden window on Windows may never produce one, which cost this app both its main window and its lyrics editor. Races it against `did-finish-load` with a timeout behind both. Media keys and the update check hang off `did-finish-load` for the same reason.
- `createWindow()` - **398**. `hiddenInset` + `trafficLightPosition` are macOS only; Windows and Linux get `titleBarOverlay`. `minHeight: 560` is deliberate.
- `DEBUG_SENTINEL` - **534**. Resolved on first ask, not at module scope: it once called `app.getPath()` during `require()`, before the app was ready.
- Secondary windows: metadata editor **640**, miniplayer **699** (`MINI_WIDTH` **762**, width locked, height 100-900, persisted). **Every new window must be added to `package.json`'s `build.files`** or it works in dev and is missing from the packaged app.
- The miniplayer is available in packaged builds. It has volume (wheel, arrow keys, and a slider in the square and lyrics layouts, sent as the absolute `volumeto` command), shuffle, repeat, auto-mix and an Up Next pane. Windows and Linux use the frameless window with its in-page close button and 22px drag strip; no OS caption buttons are drawn there, so `--caption-reserve` does not apply. `pushMiniplayerState()` bails unless `_miniplayerOpen`, which main.js keeps through `miniplayer-open-state`.
- **Updates.** Windows runs the NSIS installer silently (`installSilentlyWindows`). macOS installs in place through `mac-update.js`, **shared byte-identical with Cha0s Stream's `electron/mac-update.js`**: change one, copy it to the other. Mount the DMG, stage the new `Cascade.app` beside the installed one, verify its signature, bundle id and version, then a detached shell script waits for Cascade to quit, swaps the bundles (restoring the old one if the swap fails) and relaunches. Running from the DMG, an App Translocation copy, or an unwritable folder, or any failed check, falls back to opening the DMG. Squirrel.Mac is not an option: it requires a Developer ID signature and Cascade is ad-hoc signed. None of this protects against a malicious release uploaded to the repo; GitHub's asset digest only catches corruption. The swap script logs to `$TMPDIR/cascade-update.log` (named from the bundle, so Stream's is `cha0s-stream-update.log`). `isNewerVersion` (in `src/core/update-release.ts`) sorts `-bN` betas below their release; Stream's `isNewer` is the same logic.

The plan is `docs/mac-native-plan.md`, section "Shipping both Mac DMGs". Two Mac apps ship from one release for now, and the pipeline has to keep them apart.
- **The `mac` platform** (`src/core/release-plan.ts`). `Platform` is `desktop | mac | apple | android`; `mac` is the native app, `desktop` stays Electron on every OS, Electron's Mac DMG included. Its file is `Cascade-Native-<ver>.dmg`, deliberately without `arm64`: every updater already installed picks the first `.dmg` containing `arm64`, so none of them can be handed it. `platformOfFile` tests `mac` before `desktop` (desktop's `*.dmg` matches both) and globs are real regexes now, since `Cascade-Native-*.dmg` has its wildcard in the middle. `mac` is in `EXPLICIT_ONLY`: it is built only when a marker or manual run names it, and `[all]`, a marker with no list and `apple/` changes leave it out (plan, "Defaults and sunset" step 1; emptying the list flips that at parity). `scripts/release-plan.mjs` treats `mac` as available when `apple/` exists. `PLATFORMS` order is `desktop, mac, apple, android`, which is also the order of keys in `versions.json`.
- **Desktop's `*.dmg` still swallows the native DMG in four places**, and each one drops it by hand: the release job's copy of built files and its carry-over download (both in `build.yml`), `publish.yml`'s mirror download (`up/desktop/<ver>/`), and `desktopBuildOf`'s check that an installer proves a build (`isNativeMacInstaller`). A test in `test/release-plan.test.ts` greps the workflows for the first three. The fourth matters most: without it a release holding only the native DMG, with an unreadable `versions.json`, looks like a desktop build at the tag's version to every Windows and Linux user.
- **`macBuild` (`electron` | `native`)** is an electron-store key, unset by default, and `desktopBuildOf` / `pickInstaller` take it as an optional last argument. Unset or `electron` is byte for byte the old behavior. `native` reads versions.json's `mac` entry (no tag fallback: a tag names no native version) and requires a `Cascade-Native-<mac>.dmg` carrying that version. main.js passes it on an Apple Silicon Mac only (`macBuildPreference()`, **1034**); the native app is arm64 only.
- **"Try the native Mac app"** is the Settings, About button (`#btn-try-native-mac`, `renderer.js` **7557**; the row is hidden unless `canTryNativeMac` says arm64 macOS, and packaged builds show it disabled as "Native Mac app coming soon" until the native app is ready). IPC `try-native-mac` (`main.js` **1485**) sets `macBuild = native` and calls `checkForUpdates({ tryNative: true })`, which looks through the last 10 releases (the native app ships as a beta first), does NOT require the version to be newer (the native version is often equal to this Electron one), and opens the normal update window: download, sha256, `installInPlace`. `nativeSwitch` remembers the previous value; closing the window without a started swap, or finding no native build, restores it (`abandonNativeSwitch()`). A Mac left on `native` by a swap that failed after the quit tries native first and falls back to Electron, so it is never stranded.
- **`build.yml`** has `build-mac-native` (`xcode-27`, **229**): xcodegen, `xcodebuild archive -scheme CascadeMac` with `MARKETING_VERSION` the whole release version (a beta's `-bN` included, unlike the iOS and tvOS job: `mac-update.js` refuses a swap unless `CFBundleShortVersionString` equals what versions.json promised) and `CURRENT_PROJECT_VERSION` the run number, `codesign --force --deep --sign -`, `hdiutil create` with one `.app` and an Applications link, then mounts the DMG and checks what the updater checks. The release job's env uses `WANT_MAC` and `MAC_NATIVE` (`MAC` was already taken by the Electron job's result).
- **Site data** (`src/core/site-data.ts`): every file has a `label`, "Mac (native)" for `Cascade-Native-*.dmg`, "Mac (Electron)" for any other `.dmg`, null otherwise. The website must render it. The mirror lists `mac/<ver>/` beside `desktop/<ver>/`.
- **Changelog**: `### Mac` is a fourth platform section, printed after Desktop. The Mac updater's notes come from it (`notesBetween(entries, 'mac', ...)`). An Electron app from before this change throws on that heading when it parses CHANGELOG.md straight from GitHub (its second source), and then falls back to the release body; the website's `changelog.json` source ignores unknown platforms.
- **Bug reports** have a required "Build (Mac only)" dropdown.

## Server facts (verified against this user's live Jellyfin 10.11.11)

- Admin: `Policy.IsAdministrator` on `/Users/{id}`.
- Deletion is its OWN right: `Policy.EnableContentDeletion` plus `EnableContentDeletionFromFolders`. An admin has it implicitly; a non-admin can be granted it. See `canDeleteMedia()` in `src/core/permissions.ts`.
- `POST /Library/Refresh`, `POST /Items/{id}/Refresh`, `POST /Items/{id}` and `POST /Items/{id}/Images/Primary` are all **RequiresElevation**.
- `POST /Playlists/{id}` takes Name, Ids (the full ordered contents) and IsPublic under normal auth. **No Overview field exists.**
- `POST /Playlists/{id}/Items` takes `ids` as a query array, so comma-separated works.
- Played state is `POST`/`DELETE /UserPlayedItems/{id}` with `userId` as a query parameter. The `/Users/{id}/PlayedItems/{id}` route is gone.
- There are **no star ratings**. `POST /UserItems/{id}/Rating` is a thumbs boolean, a different field from `IsFavorite`. Decided not to build on it.
- Jellyfin exposes **no per-playlist add date**. Playlist entries are the plain track DTO plus a `PlaylistItemId`.

## House style

- No semicolons in `renderer.js` or `main.js`. Match the neighbours.
- **No em dashes anywhere**, code comments and commit messages included.
- Comments explain WHY, especially where a past bug drove the shape.
- Store values are untrusted: a corrupted setting must never reach a filter gain or a bitrate as NaN.
- Every animation belongs in the existing `prefers-reduced-motion` block.
- A disabled control must ALSO be guarded in its handler. A disabled-looking element can still be clicked programmatically.
